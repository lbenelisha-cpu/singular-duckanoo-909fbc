# Sprint 9.2.2 — העלאות גדולות ויציבות לענן

הגרסה מתקנת שני מצבים שנראו בגרסה הקודמת:

- הודעת `canceling statement due to statement timeout` בזמן עבודה מול Supabase.
- קובץ איכות גדול שנראה חלקית (למשל 6,000 רשומות) לאחר העלאה שנעצרה באמצע.

## מה השתנה

1. כל העלאה מקבלת `upload_id` חדש.
2. כל החלקים של הקובץ עולים תחילה כגרסה חדשה ונפרדת.
3. רק לאחר שכל החלקים נשמרו, המערכת מחליפה את הגרסה הפעילה.
4. אם העלאה נכשלת, הנתונים התקינים הקודמים נשארים פעילים.
5. בדיקת הבריאות אינה מבצעת יותר `COUNT(*)`, כדי למנוע timeout במסלול החינמי.
6. מוצגת התקדמות באחוזים בזמן העלאת קבצים גדולים.

## התקנה

פתח את `INSTALL_SUPABASE.sql` ב-Supabase SQL Editor והריץ את כל הקובץ. ניתן להריץ אותו גם על התקנה קיימת.
לאחר מכן העלה את הפרויקט ל-GitHub ובצע `Clear cache and deploy site` ב-Netlify.

לאחר הפריסה יש לטעון מחדש את קובץ תוצאות האיכות המלא. הכרטיס צריך להציג את מלוא מספר הרשומות, ולא 6,000 בלבד.
